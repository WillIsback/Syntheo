---
title: "Audio, capture and transcription crates"
description: "Map of the Rust crates that capture audio, detect speech, talk to STT servers and assemble the transcript."
---

This page describes the crates in `crates/` that handle audio capture, transcription and meeting detection. It helps you know which code drives which documented behavior. The end-to-end flow is described in [Architecture](/en/architecture).

In the `Cargo.toml` files, these crates are referenced by the workspace alias `syntheo-<name>` (for example `syntheo-audio-actual`), except `owhisper-client`, `owhisper-interface` and `openai-transcription`, which keep their name.

## Main chain

1. `apps/desktop/src-tauri` creates the audio provider: `syntheo-audio-actual` (`ActualAudio`), or `syntheo-audio-mock` in a development build.
2. `plugins/transcription` goes through `syntheo-transcription-core`, which re-exports `syntheo-listener-core` (live listening) and `syntheo-listener2-core` (batch import).
3. Both listeners talk to the STT server through `owhisper-client`, which relies on `openai-transcription` and `syntheo-ws-client`.
4. `syntheo-transcript` assembles the received words into segments and speakers.
5. `plugins/dictation` reuses `syntheo-audio` and `owhisper-client` for dictation.

### `crates/audio-actual`

- **Role**: the only audio provider in published builds. `apps/desktop/src-tauri/src/lib.rs` (`create_audio_provider`) instantiates it, unless `MOCK_AUDIO` is set in a `dev` or `devtools` build.
- **API**: `ActualAudio`, `AudioInput`, `AudioOutput`, `AudioSource`, `AudioStream`; re-exports `AudioProvider`, `CaptureConfig`, `CaptureFrame`, `CaptureStream` from `crates/audio`.
- **System audio capture**: `src/speaker/` contains one implementation per platform. On Linux, it relies on PulseAudio (`libpulse-binding`) and PipeWire; on Windows, on `wasapi`; on macOS, on `cidre`. The output chosen in the settings is used, otherwise the default output.
- **Capture**: `src/capture/` combines microphone and system audio (`joiner.rs`), applies echo cancellation (`echo_gate.rs`) and handles recovery after errors (`recovery.rs`).
- **Internal dependencies**: `aec`, `audio`, `audio-device`, `audio-interface`, `audio-sync`, `audio-utils`, `resampler`.
- **Affected doc pages**: [/en/meetings](/en/meetings), [/en/troubleshooting](/en/troubleshooting) (audio on Linux and Windows), [/en/data-and-privacy](/en/data-and-privacy) (audio never kept).

## Listening sessions

### `crates/listener-core`

- **Role**: live listening engine. Actors (`src/actors/`) manage the session (`session/`), the audio source (`source/`, with mutes and device tracking), the STT connection (`listener/`), the audio sweep (`audio_sweep.rs`) and reading a file at real-time pace (`file_stream/`).
- **API**: `State`, `Snapshot`, `TranscriptionMode`, `StartSessionError`, `DegradedError`, the events (`events.rs`) and live transcription (`live_transcript`).
- **Guarantee**: the `supervisor_writes_no_audio_to_session_dir` test checks that no audio file appears in the session folder.
- **Internal dependencies**: `audio`, `audio-device`, `audio-utils`, `device-monitor`, `language`, `storage`, `supervisor`, `transcript`, `vad-masking`, `owhisper-client`, `owhisper-interface`.
- **Affected doc pages**: [/en/meetings](/en/meetings), [/en/automatic-capture](/en/automatic-capture), [/en/data-and-privacy](/en/data-and-privacy), [/en/offline](/en/offline), [/en/troubleshooting](/en/troubleshooting).

### `crates/listener2-core`

- **Role**: batch transcription of an imported file. `src/batch/` offers a simple mode and a progressive mode; `upload.rs` splits the audio into in-memory MP3 segments before sending.
- **API**: `BatchRuntime`, `BatchParams`, `BatchEvent`, `BatchRunMode`; `is_supported_languages_live` / `_batch`, `suggest_providers_for_languages_live` / `_batch`; subtitle reading (`parse_subtitle_from_path`).
- **Internal dependencies**: `audio-utils`, `language`, `mp3`, `user-error`, `owhisper-client`, `owhisper-interface`.
- **Affected doc pages**: [/en/import-recordings](/en/import-recordings), [/en/languages](/en/languages).

### `crates/transcription-core`

- **Role**: single facade for `plugins/transcription`. The `listener` and `listener2` modules re-export `listener-core` and `listener2-core`. The `realtime_file` module imports a file for a real-time model: in-memory decoding, a single REST request for NVIDIA NeMo-Speech.cpp (`file_stream::rest`), otherwise the real-time stream of `file_stream`, then rendering in batch format, without writing anything to disk.
- **Internal dependencies**: `listener-core`, `listener2-core`, `owhisper-interface`.
- **Affected doc pages**: [/en/meetings](/en/meetings), [/en/import-recordings](/en/import-recordings).

### `crates/supervisor`

- **Role**: actor supervision: restart budget (`RestartBudget`, `RestartTracker`), retry with strategy (`RetryStrategy`, `spawn_with_retry`), dynamic supervisor (`dynamic`).
- **Used by**: `listener-core` (audio source restart).
- **Affected doc pages**: [/en/meetings](/en/meetings) (recovery without restarting the capture).

## Transcription and languages

### `crates/transcript`

- **Role**: turns the words received from STT into a transcript: processing (`TranscriptProcessor`), segments (`build_segments`), speaker labels (`SpeakerLabeler`, `render_speaker_label`), speaker context, post-batch refinement (`batch_refine`), live materialization and rendering.
- **Internal dependencies**: `owhisper-interface`.
- **Used by**: `listener-core`, `plugins/transcription`, `agent-access` (CLI and MCP server).
- **Affected doc pages**: [/en/meetings](/en/meetings), [/en/notes](/en/notes), [/en/contacts](/en/contacts), [/en/reference/cli](/en/reference/cli), [/en/reference/mcp](/en/reference/mcp).

### `crates/language`

- **Role**: ISO 639-1 language codes (`ISO639`, `Language`), lists of supported languages (`whisper_multilingual`, `parakeet_tdt_v3_languages`), detection (`detect`, through `whatlang`) and dominant language of a text (`dominant_language`).
- **Internal dependencies**: `whisper` (`whisper` feature, enabled by default).
- **Used by**: `detect`, `listener-core`, `listener2-core`, `owhisper-client`, `owhisper-interface`, `plugins/tantivy`, `plugins/template` (`dominant_language` command), `plugins/transcription`.
- **Affected doc pages**: [/en/languages](/en/languages).

### `crates/whisper`

No Whisper model: the crate only contains the `Language` enum of the Whisper tokenizer's languages (`whisper_index`). Only `crates/language` uses it. **Affected doc pages**: none.

### `crates/speech-probe`

On-device transcription probe (issue 682), with nothing downloaded. `hardware::read` reads in a few milliseconds AVX2, physical and logical cores, available memory, free space on the data disk, power plan (Linux: ACPI profile; Windows: active plan and battery saver), mains or battery, and GPUs with their video memory when the system reports it. `bench::run` is a micro-benchmark of about 4 s: a q8_0 matrix product with AVX2, shaped like an encoder layer, on as many threads as physical cores; it returns a throughput in GMAC/s. `predict::predict` turns that throughput into an RTF per engine (`Engine::ParakeetOnnx` or `Engine::NemoGgml`) and per profile, interpolating between points measured by the issue 680 bench. `predict::decide` applies the thresholds: full profile offered up to an RTF of 0.5, degraded profile up to 1.0, refused beyond, or without AVX2, under 1.5 GB of free memory, under 2 GB of disk or when the disk cannot be found; outside the measured range, the prediction is never more favourable than the end point. Exposed by the `probe_local_transcription` command of `plugins/transcription`: one probe at a time, refused during a capture, when the capture state does not answer, and by the relay; a capture that starts interrupts it (verdict `interrupted`). The `probe` example prints the probe as JSON, to calibrate a reference machine. **Affected doc pages**: [/en/on-device-transcription](/en/on-device-transcription).

### `crates/speech-host`

Host of the `syntheo-speech` module in the application (issue 684). `verify::verify` checks the module folder before every launch. First the signed manifest (`manifest`, issue 683): minisign signature with the module key (`MODULE_PUBLIC_KEY`, separate from the update key; while it is empty, no module is loaded), target, protocol, minimum application version and minimum module version (`MIN_MODULE_VERSION`). Then `files.sha256`, which must list exactly the manifest's files: size and SHA-256 checksum of each, with no unlisted file, no symlink, and no path leaving the folder. What runs is what was hashed: the binary and its libraries are copied into a fresh private folder per launch (0700 on Linux, owner-only DACL on Windows); models are inherited by file descriptor on Linux (`/proc/self/fd/N` link) and locked along with the folders of their path on Windows; all of it is kept until the process dies. The manifest build number cannot go down (`speech.floor` floor). The module's working directory is never its own folder. `SpeechHost::target` starts the module when needed: cleared environment, a random 256-bit token written to standard input, announcement read from standard output. The token and port stay in memory, never in a log, a setting, the command line or the module's environment. A dead module is restarted with a new token and a new port; the old port is never reused. Every launch attempt counts, successful or not: beyond 3 in 10 min, the host refuses any launch until the window ends, and the count resets after a launch stays alive for 1 min. A module rejected by verification is not checked again before the capture ends. Permanent refusals (policy, missing or altered module, crash loop, module proof refused) surface as `DegradedError::OnDeviceUnavailable` or `OnDeviceAuthenticationFailed` and are not retried by the session supervisor; only a failed launch is. `install` installs a module from a prepared folder: signed manifest (before any other read) and closed list of the source folder, a bounded copy hashed on the fly, a check of the copy, then a single rename into place, rolling back to the old module if it fails; the anti-rollback floor only rises after success, and leftover temporary folders are cleaned. During an installation, `target()` refuses at once (`installing`); `status` reads the state without hashing. `commission` runs the commissioning (issue 686): each profile is measured for about 30 s on the audio shipped with the module, in the order of the bench 680 conclusion, the first profile under 2 s of final latency at the 95th percentile with no drift is kept, and the result is saved (`speech.commissioning.json`) and applied to captures (one or two streams, diarization or not); `load` returns the load metrics published by the module (lag, RTF, diarization level). `SpeechHost::stop` closes standard input, then stops the process after 3 s. Wired by `plugins/transcription` (`on_device`): the "On this computer" source has a reserved internal address (`owhisper_client::ON_DEVICE_BASE_URL`), resolved by `ListenerRuntime::on_device_target` on every listener connection. The client then connects with the peer proof (`OnDeviceToken`, `ws_client::PeerProof`): nothing is sent before the module's proof is verified, and a wrong proof closes the connection with no retry. The module stops when the capture ends. The managed setting `on_device_transcription_enabled` set to `false` forbids loading it. It is read from `managed_settings.json` (`db_app::load_managed_policy`) and kept in memory, never from the database, which the webview can rewrite. **Affected doc pages**: [/en/on-device-transcription](/en/on-device-transcription), [/en/security](/en/security).

### `apps/speech`: `syntheo-speech` module

On-device transcription module (issue 681): a separate process that the application starts and stops, reachable only on the loopback, speaking the NeMo-Speech.cpp realtime protocol, the one of the `nvidia` adapter in `crates/owhisper-client`. It is a **separate Cargo workspace**, with its own `Cargo.lock`: engine A (`parakeet-rs`, ONNX Runtime) pins a different `ort` version from the application's, and the module is built by its own workflow.

- **Engines behind a trait** (`engine::Engine`, `engine::Recognizer`): A, `parakeet::ParakeetEngine` (streaming Nemotron 3.5, per-channel int8, and Nemotron-3 diarization), is implemented; B can plug in later.
- **Launch**: the token (at least 128 bits) arrives on standard input, never on the command line; the module listens on `127.0.0.1`, on a free port, announces it as JSON on standard output and stops when standard input closes.
- **Local channel** (`auth`, `server`): the token never travels. The client sends a nonce and a proof, and the module answers with its own: HMACs of the token bound to the nonce, both ports of the connection and the direction, which prevents relaying and reflection. A nonce is accepted only once (replay refused). `Origin` header refused; `Host` limited to the loopback. Handshake bounded in time and number, concurrent sessions bounded, audio queue bounded.
- **Logs**: durations and counts, never transcribed text.
- **Load** (`load`, issue 686): lag and RTF of each session; beyond 2 s of lag, diarization is spaced out then turned off, and restored under 1 s; metrics are published every 5 s on standard output.
- **Build** (issue 683): `build-speech.yml` builds the module for Linux and Windows x86-64, with no shared cache. The ONNX Runtime archive is checked against our own pin (`supply-chain/check_ort.py`, `ort.tsv`). The workflow outputs a CycloneDX SBOM, crate notices (`cargo about`), licenses and notices of origin under `licenses/`, `manifest.json` and `files.sha256` (`supply-chain/make_manifest.py`), and the manifest signature on request from main (`speech-signing` environment). The int8 models are rebuilt identically from pinned sources (`models/models.json`, `models/quantize.py`).
- **Tests**: utterance segmentation, timestamps and speakers tested without the model (`segment`); contract with the `nvidia` adapter over a fake engine (`fake-engine` feature, never shipped); handshake (relay, replay, reflection, silent connections); no outbound connection from the real binary (Linux); a real-model run when `SYNTHEO_SPEECH_MODELS` and `SYNTHEO_SPEECH_AUDIO` are set.

**Affected doc pages**: [/en/on-device-transcription](/en/on-device-transcription).

## Meeting detection

### `crates/detect`

- **Role**: watches the computer to trigger automatic capture. Modules behind features: `mic` (microphone used by another app; PulseAudio on Linux), `list` (installed apps), `app`, `zoom`, `sleep` (sleep mode), `screen` (screen capture through `xcap`), `language`. `meeting_ax` reads macOS accessibility.
- **API**: `Detector`, `DetectEvent`, `DetectCallback`, `new_callback`, `BackgroundTask`.
- **Internal dependencies**: `language`; `bundle` on macOS.
- **Used by**: `plugins/detect` (features `mic`, `list`, `language`, `sleep`, `screen`).
- **Affected doc pages**: [/en/automatic-capture](/en/automatic-capture).

## Pointers for the documentation

- Change of audio platform, device or system capture: `crates/audio-actual`, `crates/audio-device`, `crates/device-monitor`. Update [/en/meetings](/en/meetings) and [/en/troubleshooting](/en/troubleshooting).
- New STT protocol or provider: `crates/owhisper-client`. Update [/en/ai-setup](/en/ai-setup), [/en/conformite/rgpd](/en/conformite/rgpd) and [/en/architecture](/en/architecture).
- Change of import formats or batch transcription: `crates/listener2-core`, `crates/transcription-core`. Update [/en/import-recordings](/en/import-recordings).
- Change of supported languages: `crates/language`, `crates/listener2-core`. Update [/en/languages](/en/languages).
- Any audio write to disk contradicts [/en/data-and-privacy](/en/data-and-privacy) and the [architecture](/en/architecture) guarantees.
