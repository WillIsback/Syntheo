Syntheo is a local client. It has no account, no vendor server and no sync, and sends no telemetry. Your data stays on your computer; only the inference servers that **you** set up receive meeting content.

For a complete GDPR assessment (data table, network flows, technical safeguards, responsibilities), see [Syntheo Desktop and the GDPR](/en/conformite/rgpd).

## What is stored, and where

Everything is in the app's data folder:

| System | Data folder |
| --- | --- |
| Linux | `~/.local/share/syntheo` |
| Windows | `%APPDATA%\syntheo` |

| Data | Storage |
| --- | --- |
| Transcripts, notes, summaries, contacts, folders (project thread, next meeting agenda, default template), automations, settings | Local SQLite database `app.db` |
| Full-text search index | Data folder (indexed copy of transcripts and notes) |
| Technical logs | The app's log folder, with sensitive content masked (keys and tokens, addresses, identifiers) and size-based rotation. For a failed webhook, only the host is logged, never the URL path |
| Inference server API keys and webhook signing secrets | System keychain (Secret Service on Linux, Credential Manager on Windows), never in plain text in the database. With no keychain available on Linux, a webhook secret stays in the database |
| Exports | Folder chosen in "Export location" (**Settings → Profile**) |
| On-device transcription models, if installed | `speech/models` in the app data folder (`~/.local/share/fr.willisback.syntheo` on Linux, `%APPDATA%\fr.willisback.syntheo` on Windows), with the commissioning result (`speech/commissioning.json`); see [Transcribe on this computer](/en/on-device-transcription) |
| Audio | **Nowhere**: see below |

<Warning>
  Syntheo does not encrypt the local database. Turn on disk encryption (BitLocker on Windows, LUKS or the encryption offered at installation on Linux) and lock your session: this is what protects your notes if the computer or a backup is lost. Do not edit `app.db` by hand: you risk corrupting your notes. For a portable copy, use export.
</Warning>

On Linux, Syntheo restricts its data folder to your account: the folder is `0700`, the database and logs `0600`, corrected at every start. Backups left by a database reset (`app.db.<timestamp>.bak`, where the timestamp is in Unix seconds) are deleted after 30 days; the most recent one is always kept.

## Audio is never kept

A meeting cannot be replayed (一期一会, "one encounter, one time only"): only the note remains. See [The Syntheo spirit](/en/philosophy).

Capture audio lives in memory just long enough to be sent to your transcription server, then disappears. Syntheo writes no audio file, not even a temporary one:

- no meeting recording, no audio player, no re-transcription afterwards;
- dictation produces its audio in memory;
- importing an audio file reads the file where it is, without copying it into the data folder.

When you mute the microphone or system audio during listening, Syntheo sends silence in place of that source: what it captures does not leave your computer. See [Record a meeting](/en/meetings), section "Mute the microphone or system audio".

As a result, if transcription stops (network outage, server unreachable or down), Syntheo says so and reconnects. If the server refuses the key or the settings, Syntheo does not retry: fix them in **Settings → Transcription**, then restart listening. When it reconnects, it replays the last seconds kept in memory (about fifteen at most) to the new stream: a short outage leaves no gap. Beyond that, the passage before those last seconds is missing from the transcript and cannot be recovered, since no audio is saved.

## What leaves your computer

| Destination | What is sent | When |
| --- | --- | --- |
| Your transcription server | The audio of the capture, the dictation or the imported file | During transcription |
| The [On this computer](/en/on-device-transcription) program, on your computer's loopback | The recording audio, if chosen: nothing leaves the computer | During an "On this computer" recording |
| The sources of the on-device transcription models: Syntheo's GitHub release (`github.com`, redirected to `release-assets.githubusercontent.com`), then Hugging Face (`huggingface.co`, redirected to its content servers under `hf.co`) as a fallback, or the mirror set by your organization (`speech_models_urls`); HTTPS redirects are followed | HTTPS requests for the model files, nothing about your meetings; these hosts see your IP address | Only when you choose **Download the models**; no connection if you install them from a folder |
| Your summary server | The text needed for the task: transcript, notes, summary template instructions, chat question. For the summary, the images pasted in the note (10 at most, downscaled), if the model reads images; to check that, a test image provided by Syntheo | Summary, chat, "Suggest sections", a folder's project thread and agenda, an automation's "Generate" step |
| Your [webhooks](/en/reference/webhooks)' addresses | Meeting events (note, summaries, participants, transcript) | At each event, if you added an endpoint |
| The address of an [automation](/en/automations)'s webhook step | The content you put in it | When the automation runs |

No header identifies your device. Syntheo never falls back to another service if your server does not respond.

Apart from the servers and addresses you configure (inference, webhooks) and the "On this computer" models (table above), only updates leave the computer, with no meeting content: Syntheo reads `latest.json` on GitHub 15 seconds after startup (can be turned off) or when you start the check, and this file also carries the new version's release notes. The installer is downloaded only if you choose to update.

An image hosted on another site, in a summary, an edit proposal or a chat answer, is never loaded: its alternative text shows instead, and no request goes to that site.

Nothing is sent to the vendor: no account, no usage statistics, no error reports. The update check, on by default and optional, sends no personal data; GitHub sees the computer's IP address. See [Update](/en/desktop-installation#update).

<Note>
  An inference server run by a third party becomes your processor within the meaning of the GDPR (Art. 28): check the contract and where the data is located. A self-hosted server stays under your control.
</Note>

## Rework measurement (beta)

For the beta, Syntheo can measure how much you reworked a summary before sending it. This feature is **off by default**: turn on "Measure rework of summaries" in **Settings → Advanced → Privacy**. An administrator can turn it off through `managed_settings.json` (keys `measurement_enabled` and `calibration_enabled` set to `false`, see [Security](/en/security#enterprise-deployment)).

In the summary menu, "Measure rework…" opens a window where you paste the version you sent, or drop a `.txt`, `.md`, `.html` or `.docx` file. The calculation runs on your computer, without AI or network, with the same rule as the [`syntheo mesure`](/en/reference/cli#mesure-command) command. It shows raw numbers: words of content reworked per 100 generated words, and names or acronyms corrected.

- **What is kept**: counts only (words generated, added, deleted, replaced), per summary and per section identified by its rank and its role (decisions, actions or other), with the version of the calculation rule, the status of the measurement (ok, doubtful or refused) and its control metrics (numbers), in the local database. Added to these, only while measurement is on: a random pseudonym; a fingerprint with a local key of corrected terms, never the terms, the key being destroyed when you erase; each summary generation with the date of its first file export and first share (copy or webhook); and a copy of the summary as generated, to compare it, cleared when measurement is turned off and never exported.
- **What is never kept**: the sent version, excerpts, headings. Pasted text lives only in the window and disappears when it closes. The measurement tables refuse any text.
- **Nothing is sent.** "Export my measurements…" shows the whole pseudonymized file before you save it; you hand it over yourself. Its content is described in [Beta](/en/beta).

**Calibration mode**, a separate setting also off by default, lets you check the rule by hand: after a measurement, each difference is shown with its two excerpts, and you choose the true class: content, lexical, or artifact (a difference that is not a real one, caused by how the text was read). The automatic class only appears after your choice, so it does not sway it. The agreement (per difference and weighted by words, artifacts apart) is shown and can be copied; only the content/lexical agreement matrix (numbers) can be saved. Excerpts and your line-by-line choices stay on screen: they go neither to the database, nor to the log, nor to any export.

## Delete your data

- **A meeting**: delete it in the app. For a few seconds, **Undo** brings it back. After that, it is erased for good: its folder on disk (attachments included), then all its content in the local database (title, notes, transcripts, earlier versions, measurements), and search. The bytes are zeroed in the database and its journal, and the search index is reorganized: the text does not stay readable in the files. If Syntheo is closed before this finishes, the erasure completes at a later launch, once 10 minutes have passed since the deletion: a meeting deleted less than 10 minutes before a launch is erased at the launch after that. A meeting with an attachment or a copy that depends on a sync is not erased from the database. Meetings deleted with a version earlier than 0.8.1 are erased the same way at the first launch of 0.8.1. That same launch rewrites the database once in the background, to erase the leftovers that earlier versions left in the file (earlier versions of an edited or deleted note). If the database is busy at that moment, the rewrite runs again at the next launch.
- **An API key**: in **Settings → Transcription** or **Settings → Synthesis**, open "Advanced", click "Reset this server…", then "Reset". The address and the key are forgotten; the key is removed from the keychain.
- **Your beta measurements**: in **Settings → Advanced → Privacy**, "Erase my measurements…", then confirm. The counters, the calibration, the term and summary tracking, the copy of generated summaries and the pseudonym are erased, and measurement is turned off.
- **Everything**: run a [complete uninstall](/en/uninstall), which removes the database, logs, cache, configuration and API keys, then delete the exports you produced.

## Inform participants

You are the data controller: inform participants before recording a meeting. In France, recording a private conversation without their knowledge is punishable under Article 226-1 of the Penal Code.

When each capture starts, Syntheo shows a reminder. It is on by default. To turn it off, turn off "Remind participants about recording" on the "Meetings" screen:
