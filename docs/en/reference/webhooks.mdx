Webhooks let Syntheo send meeting events to your own service. They are built into the desktop app: the app itself sends the requests, without going through any intermediate server. Configure them in **Settings → Developers**, "Webhooks" section.

<Warning>
  Meeting events contain the note, the summaries, the participants, the action items and the full transcript text. Only add a trusted endpoint. As for inference servers, HTTPS is required; unencrypted HTTP is only accepted to this computer or a private network, after confirmation, with a permanent reminder.
</Warning>

To read meeting data instead of receiving it, use the [CLI](/en/reference/cli) or the [local MCP server](/en/reference/mcp).

<Note>
  This page describes the webhooks in Settings. The "Send to an address (webhook)" automation step is separate: it sends the JSON body you write, without a signature or retries. See [Automations](/en/automations#send-to-an-address-webhook).
</Note>

## Add an endpoint

1. Open **Settings → Developers**.
2. In the "Webhooks" section, enter an `https://` URL (or `http://` to this computer or a private network, to confirm), without credentials (`user:password@` is rejected), then click "Add webhook". A public `http://` webhook saved by an earlier version is marked blocked and no longer receives anything.
3. Copy the signing secret (`whsec_...`) with "Copy".
4. Click "Test" to send a `webhook.test` delivery and check that your service responds.

<Note>
  The signing secret is shown only once. Save it before leaving the page: Syntheo doesn't show it again afterwards. It is kept in the system keychain, not in the database.
</Note>

A new endpoint receives "All events". Each row shows the state of the last delivery. Use "Pause" to suspend an endpoint without deleting it, then "Enable" to resume it. The trash icon deletes it.

You can configure at most 64 endpoints.

## Events

Syntheo sends each event as a JSON `POST` request, as long as the desktop app is open.

| Event | Triggered when |
| --- | --- |
| `meeting.completed` | A capture ends. |
| `note.enhanced` | An AI summary is generated for a meeting. |
| `webhook.test` | You start a test delivery. |

The JSON envelope has this shape:

```json
{
  "id": "evt_...",
  "event": "note.enhanced",
  "created_at": "2026-07-28T09:00:00.000Z",
  "data": {
    "meeting": { "id": "...", "title": "...", "note": {...}, "summaries": [...], "participants": [...], "action_items": [...] },
    "transcript_text": "..."
  }
}
```

For `webhook.test`, `data` only contains a `message` field.

## Delivery and retries

Each request times out after 10 seconds. On failure, Syntheo retries after 5 seconds, then after 30 seconds. A `webhook.test` delivery makes only one attempt.

Syntheo does not follow redirects. A 3xx response counts as a failure, like any non-2xx response: the last delivery status shows only the host the server redirects to, never the path. Enter the final address directly, for example with `https://` if your server redirects HTTP.

Each request contains these headers:

| Header | Content |
| --- | --- |
| `x-syntheo-event` | Event name. |
| `x-syntheo-delivery` | Unique delivery ID (the same for all its attempts). |
| `x-syntheo-timestamp` | Unix timestamp, in seconds. |
| `x-syntheo-signature` | `sha256=<hex>`: HMAC-SHA256 of the raw request body, computed with the endpoint's `whsec_...` secret. Kept for existing integrations. |
| `x-syntheo-signature-v2` | `t=<timestamp>,v1=<hex>`: HMAC-SHA256 of `<timestamp>.<raw body>`, with the same secret. The timestamp is the one in `x-syntheo-timestamp`; since it is signed, it lets you reject a replayed delivery. |

## Verify the signature

Prefer checking `x-syntheo-signature-v2`. Compute the HMAC over `<timestamp>.` followed by the exact raw body, before any JSON parsing, and reject a timestamp more than 5 minutes away from your server's clock:

```js
import crypto from "node:crypto";

const TOLERANCE_SECONDS = 300;

function verifySyntheoWebhook(rawBody, header, secret) {
  // header: value of x-syntheo-signature-v2, "t=1764000000,v1=<hex>"
  const parts = Object.fromEntries(
    String(header ?? "").split(",").map((part) => part.split("=", 2)),
  );
  const timestamp = Number(parts.t);
  if (!Number.isInteger(timestamp)) return false;
  if (Math.abs(Date.now() / 1000 - timestamp) > TOLERANCE_SECONDS) return false;
  const expected = crypto
    .createHmac("sha256", secret)
    .update(`${timestamp}.`)
    .update(rawBody)
    .digest("hex");
  const received = String(parts.v1 ?? "");
  return (
    Buffer.byteLength(received) === Buffer.byteLength(expected) &&
    crypto.timingSafeEqual(Buffer.from(received), Buffer.from(expected))
  );
}
```

Each attempt (including a retry after a failure) carries a new timestamp and a new signature. To process a retried delivery only once, store its `x-syntheo-delivery` or the payload `id`.

The legacy `x-syntheo-signature` header (`sha256=` followed by the HMAC of the body alone) is still sent; it does not protect against replay.

## Limits

<Warning>
  Deliveries only happen while the desktop app is open. Events that occur while it is closed are lost: they are not queued.
</Warning>

Syntheo sends an event to at most 64 endpoints and runs at most 4 deliveries at the same time.
