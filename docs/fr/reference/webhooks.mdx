Les webhooks permettent à Syntheo d'envoyer des événements de réunion vers votre propre service. Ils sont intégrés à l'application de bureau : c'est l'application elle-même qui envoie les requêtes, sans passer par aucun serveur intermédiaire. Configurez-les dans **Paramètres → Développeurs**, section « Webhooks ».

<Warning>
  Les événements de réunion contiennent la note, les synthèses, les participants, les actions à mener et le texte complet de la transcription. N'ajoutez qu'un point de terminaison de confiance. Comme pour les serveurs d'inférence, HTTPS est exigé ; le HTTP non chiffré n'est accepté que vers ce poste ou un réseau privé, après confirmation, avec un rappel permanent.
</Warning>

Pour lire les données de réunion plutôt que de les recevoir, utilisez la [CLI](/fr/reference/cli) ou le [serveur MCP local](/fr/reference/mcp).

<Note>
  Cette page décrit les webhooks des Paramètres. L'étape d'automatisation « Envoyer vers une adresse (webhook) » est distincte : elle envoie le corps JSON que vous composez, sans signature ni nouvelle tentative. Voir [Automatisations](/fr/automations#envoyer-vers-une-adresse-webhook).
</Note>

## Ajouter un point de terminaison

1. Ouvrez **Paramètres → Développeurs**.
2. Dans la section « Webhooks », saisissez une URL en `https://` (ou `http://` vers ce poste ou un réseau privé, à confirmer), sans identifiants (`utilisateur:motdepasse@` est refusé), puis cliquez sur « Ajoutez un webhook ». Un webhook en `http://` public enregistré par une version antérieure est marqué bloqué et ne reçoit plus rien.
3. Copiez le secret de signature (`whsec_...`) avec « Copier ».
4. Cliquez sur « Test » pour envoyer une livraison `webhook.test` et vérifier que votre service répond.

<Note>
  Le secret de signature n'est affiché qu'une seule fois. Conservez-le avant de quitter la page : Syntheo ne l'affiche plus ensuite. Il est gardé dans le trousseau du système, pas dans la base.
</Note>

Un nouveau point de terminaison reçoit « Tous les événements ». Chaque ligne affiche l'état de la dernière livraison. Utilisez « Pause » pour suspendre un point de terminaison sans le supprimer, puis « Activer » pour le reprendre. L'icône de corbeille le supprime.

Vous pouvez configurer au plus 64 points de terminaison.

## Événements

Syntheo envoie chaque événement en requête `POST` JSON, tant que l'application de bureau est ouverte.

| Événement | Déclenché quand |
| --- | --- |
| `meeting.completed` | Une capture se termine. |
| `note.enhanced` | Une synthèse IA est générée pour une réunion. |
| `webhook.test` | Vous lancez une livraison de test. |

L'enveloppe JSON a cette forme :

```json
{
  "id": "evt_...",
  "event": "note.enhanced",
  "created_at": "2026-07-28T09:00:00.000Z",
  "data": {
    "meeting": { "id": "...", "title": "...", "note": {...}, "summaries": [...], "participants": [...], "action_items": [...] },
    "transcript_text": "..."
  }
}
```

Pour `webhook.test`, `data` contient seulement un champ `message`.

## Livraison et nouvelles tentatives

Chaque requête expire après 10 secondes. En cas d'échec, Syntheo réessaie après 5 secondes, puis après 30 secondes. Une livraison `webhook.test` ne fait qu'une tentative.

Syntheo ne suit pas les redirections. Une réponse 3xx compte comme un échec, comme toute réponse hors 2xx : l'état de la dernière livraison indique seulement l'hôte vers lequel le serveur redirige, jamais le chemin. Saisissez directement l'adresse finale, par exemple en `https://` si votre serveur redirige le HTTP.

Chaque requête contient ces en-têtes :

| En-tête | Contenu |
| --- | --- |
| `x-syntheo-event` | Nom de l'événement. |
| `x-syntheo-delivery` | Identifiant unique de la livraison (identique pour toutes ses tentatives). |
| `x-syntheo-timestamp` | Horodatage Unix, en secondes. |
| `x-syntheo-signature` | `sha256=<hex>` : HMAC-SHA256 du corps brut de la requête, calculé avec le secret `whsec_...` du point de terminaison. Gardé pour les intégrations existantes. |
| `x-syntheo-signature-v2` | `t=<horodatage>,v1=<hex>` : HMAC-SHA256 de `<horodatage>.<corps brut>`, avec le même secret. L'horodatage est celui de `x-syntheo-timestamp` ; étant signé, il permet de refuser une livraison rejouée. |

## Vérifier la signature

Vérifiez de préférence `x-syntheo-signature-v2`. Calculez le HMAC sur `<horodatage>.` suivi du corps brut exact, avant tout parsing JSON, et refusez un horodatage écarté de plus de 5 minutes de l'heure de votre serveur :

```js
import crypto from "node:crypto";

const TOLERANCE_SECONDS = 300;

function verifySyntheoWebhook(rawBody, header, secret) {
  // header : valeur de x-syntheo-signature-v2, « t=1764000000,v1=<hex> »
  const parts = Object.fromEntries(
    String(header ?? "").split(",").map((part) => part.split("=", 2)),
  );
  const timestamp = Number(parts.t);
  if (!Number.isInteger(timestamp)) return false;
  if (Math.abs(Date.now() / 1000 - timestamp) > TOLERANCE_SECONDS) return false;
  const expected = crypto
    .createHmac("sha256", secret)
    .update(`${timestamp}.`)
    .update(rawBody)
    .digest("hex");
  const received = String(parts.v1 ?? "");
  return (
    Buffer.byteLength(received) === Buffer.byteLength(expected) &&
    crypto.timingSafeEqual(Buffer.from(received), Buffer.from(expected))
  );
}
```

Chaque tentative (y compris une nouvelle tentative après un échec) porte un nouvel horodatage et une nouvelle signature. Pour ne traiter qu'une fois une livraison réessayée, enregistrez son `x-syntheo-delivery` ou l'`id` de la charge utile.

L'en-tête historique `x-syntheo-signature` (`sha256=` suivi du HMAC du corps seul) reste envoyé ; il ne protège pas contre le rejeu.

## Limites

<Warning>
  Les livraisons n'ont lieu que pendant que l'application de bureau est ouverte. Les événements survenus pendant qu'elle est fermée sont perdus : ils ne sont pas mis en file d'attente.
</Warning>

Syntheo envoie un événement à 64 points de terminaison au plus et exécute au plus 4 livraisons simultanées.
